## P0 修复实施（5 项全部完成）

改动文件：`electron/main.js`、`electron/preload.js`、`src/App.tsx`、
`src/types/global.d.ts`、`.gitignore`、`default.profraw`（取消跟踪，文件保留在磁盘）。

### 关键实现决策
- **沙箱**：没有直接删开关，而是 `SANDBOX_DISABLED = !app.isPackaged && env === '1'`。
  原因：**当前执行环境无法初始化 Chromium 沙箱**（`sandbox initialization failed:
  Operation not permitted`），这正是当初加 `no-sandbox` 的根因；直接删会让开发者在同类
  环境无法启动。用 `!app.isPackaged` 保证打包产物永远强制开启。
  逃生口：`PHOTOMINDER_DISABLE_SANDBOX=1 npm run electron:dev`。
- **路径白名单**：会话级 `authorizedRoots` / `authorizedFiles` 两个 Set +
  `canonicalize`（realpath → resolve 兜底）+ `isPathAuthorized`（`path.relative`
  判定，避免 `/a/bc` 被误判在 `/a/b` 之下）。
  授权入口仅 6 处：`openImportDialog`、`choose-directory`、`scan-directory`、
  `watch-directory`、`check-paths`、新增的 `authorize-paths`（拖放）。
  校验点：`pm://file`（403）+ 14 个 handler。
- **体积闸门**：`read-file` 64MB（源文件 + HEIC 转码产物各判一次，先 stat 后读）、
  `ai-analyze` 20MB base64。闸门必须在读取之前。
- **顺带修掉的真实漏洞**：`write-file-unique` 此前 `path.join(targetDir, fileName)`
  未做 basename 归一化，`../../` 可写出授权目录之外。

### 可复用验证手法（重要）
**打桩 electron 加载真实 main.js 做集成测试**：用 `Module._load` 拦截
`require('electron')` 返回桩对象（app/ipcMain/dialog/shell/protocol/nativeImage/
clipboard），捕获 `ipcMain.handle` 注册的 handler 与 `protocol.handle` 的 handler，
再直接调用它们断言行为。注意两点坑：
1. `setupProtocol()` 注册在 `app.on('ready')` 回调里，桩的 `app.on` 必须捕获该回调并手动触发；
2. `app.getAppPath` 也要桩，否则启动时会打印 env 加载警告。
本次共 37 项断言全部通过，脚本在 `/tmp/integration_test.js`（临时，未入库）。

### 环境注意
- 用 Bash 工具跑 `grep` 对本项目文件常返回空（改用 Grep 工具）。
- heredoc 里写 `${...}` 会被 zsh 当参数展开报 `Bad substitution`，
  改用 Write 工具先落盘再执行。
- `electron .` 在 Bash 工具里可能被注入 `ELECTRON_RUN_AS_NODE`，
  表现为 `require('electron')` 返回字符串 → 解构出 undefined →
  `app.commandLine` / `protocol` 报 TypeError。这不是代码问题；
  直接从 shell 跑 `node_modules/electron/dist/Electron.app/Contents/MacOS/Electron .`
  即可正常启动。
