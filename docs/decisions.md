## ADR-001 · 个人自用、纯本地优先

**决策**：产品定位是维护者个人自用的 macOS 本地照片整理工作台，不对外分发。
除用户显式触发的 AI 分析、可关闭的更新检查、人像页首次使用的模型下载外，不引入任何网络能力。

**理由**：个人自用意味着不需要账号、遥测、云同步、多端协作；把复杂度留给真正影响「不丢数据」的地方。

**后果**：不接第三方 SDK、不上报、不拉远程配置；新增依赖前先问是否破坏纯本地与 DMG 体积。

## ADR-002 · 品牌双轨

**决策**：界面显示名统一为「时光画框」，副标题「本地照片整理工作台」；
`package.json` 的 `productName` / `appId`、数据目录、DMG 文件名、导出文件的 `payload.app` 一律保留 `PhotoMinder`。

**理由**：改 `productName` 会迁移 `userData`，导致现有收藏 / 标签失联；改 `payload.app` 会让旧备份无法导入。
前者是界面承诺，后者是数据格式标识，两者职责不同。

**后果**：系统级应用菜单与 DMG 文件名保留英文，属受控例外。

**守卫**：`tests/unit/branding.test.ts` 静态断言两处边界。

## ADR-003 · 内容指纹做持久化主键

**决策**：`Photo.fileId = sha256(size + 头尾各 64KB) 截 128 bit`，收藏 / 隐藏 / 标签 / 时间修正 / 智能相簿 / AI 结果都按 `fileId` 记录。
`Photo.id` 只做会话内唯一 id，不用于持久化。

**理由**：文件重命名、移动、删除后重新导入，标注仍能续上；按路径记录会在改名 / 挪目录后全部失联。

**后果**：需要迁移器把旧路径键换算成指纹；不可达记录进 `orphans`，供「路径重连」使用。
不要重新引入 `rekeyPathData` / `dropPathData` 那条补丁链。

**守卫**：`migration-version-guard.test.cjs`、`data-assets.test.cjs`。

## ADR-004 · 会话级路径授权

**决策**：主进程维护会话级 `authorizedRoots` / `authorizedFiles`。
只有 6 个入口能产生授权：导入对话框、选择目录、扫描目录、监听目录、路径探测、拖放授权。
任何接收渲染层路径的 IPC handler 入口必须 `isPathAuthorized()`；`pm://` 每次请求都校验，未授权 403。

**理由**：渲染进程可能加载被当作图片的内容（如 SVG），必须假设它能构造请求但不能越权。
「隐式信任」的入口每多一个，安全边界就薄一层。

**后果**：新增路径类 IPC 必须走授权入口，不能为了「方便」加白名单。

**守卫**：`ipc-security.test.cjs`（未授权拒绝、六条链路、体积闸门）。

## ADR-005 · 沙箱 + CSP + 体积闸门

**决策**：沙箱默认开启，仅未打包且显式 `PHOTOMINDER_DISABLE_SANDBOX=1` 时关闭；
CSP 唯一定义在 `electron/lib/csp.cjs`，响应头与构建期 `<meta>` 共用；
读取体积闸门放在读取之前（`read-file` 64MB、`ai-analyze` 20MB）。

**理由**：Electron 默认配置偏松；这三项是内容级攻击与内存耗尽的主要收敛点。

**后果**：打包产物永远强制开启沙箱；新增读取入口先 `stat` 再决定是否读。

**守卫**：`ipc-security.test.cjs`、Electron 冒烟（CSP 违规 0）。

## ADR-006 · dHash 单一实现

**决策**：算法本体只在 `electron/lib/dhash.cjs`；渲染层通过 Vite 插件在 dev 期做 CJS→ESM 机械转换，构建期用 rolldown 自带互操作。
渲染层只在主进程解不了时降级使用。

**理由**：同一算法两份实现必然漂移；主进程是 CommonJS，渲染层是 ESM，直接共享需要构建期处理。
插件只搬壳，不含算法知识；导出键名由 Node 直接 `require` 得到，避免声明与实现漂移。

**后果**：不要复制算法到 `src/`；改算法只改一处并跑跨入口一致性测试。

**守卫**：`tests/unit/dhash.test.ts`。

## ADR-007 · AI 密钥只在主进程

**决策**：密钥由主进程读取本机明文配置（`ai-config.json`）并代理请求；
`ai-config-get` 只返回 `hasApiKey` + 尾号掩码，渲染层可以写入新密钥但读不回旧值；
导出配置不包含密钥；日志与错误信息不出现明文。

**理由**：渲染进程是攻击面更大的一侧；即使被攻破，也不应直接拿到长期密钥。
明文落盘是「个人自用、单机本地」定位下的既定取舍（TODO X1），不是遗漏。

**后果**：设置弹窗只能显示掩码；新增 AI 能力必须经主进程。

**守卫**：`ai-config-privacy.test.cjs`。

## ADR-008 · 分层依赖 + 棘轮基线

**决策**：用静态测试把「谁可以 import 谁」变成可执行断言；
无法一次清零的历史违规用「基线 + 只降不升」的棘轮管理。

**理由**：口头约定会漂移；一次性大重构风险高。棘轮让债务可见、可还、不可新增。

**后果**：新增文件不在基线内，出现即失败；修完一处要下调基线并记录日期。

**守卫**：`layering.test.cjs`。

## ADR-009 · 文档单一事实源

**决策**：同一事实只允许一个地方说「算数」：
版本号认 `package.json`，任务状态认 `TODO.md`，方向认 `ROADMAP.md`，已交付认 `CHANGELOG.md`，技术结论认 `CODE_REVIEW.md`，架构认 `docs/architecture.md`。
测试数量、文件行数等易漂移数字不写进文档正文，以命令输出为准。

**理由**：agent coding 最怕「四份文档互相矛盾」，模型会随机选一份执行。
把事实源固定下来，冲突时才有裁决顺序。

**后果**：历史快照保留原文并标注时间；新增文档先登记到 `docs/README.md`。

**守卫**：`tests/unit/docsConsistency.test.ts`（版本一致、链接可解析、模块清单不遗漏）。

## ADR-010 · 主进程按域模块化

**决策**：`electron/main.js` 只做组合根（窗口 / 菜单 / 协议 / IPC 注册 / 生命周期）；
领域逻辑放 `electron/main/*.cjs`；基础设施放 `electron/lib/*.cjs`。
模块不得反向 `require` 入口。

**理由**：单文件承载全部 IPC 与文件操作会让启动路径难以测试、改动互相牵连。

**后果**：继续按域拆分（见 `docs/architecture.md` §7），每次行为零变化、单独提交。

**守卫**：`layering.test.cjs`（主进程无反向依赖）、`ipc-contract.test.cjs`。

## ADR-011 · 明确不做

| 事项 | 理由 |
| --- | --- |
| CI | 个人自用 + 本机环境限制；用 `npm run verify` 一条命令替代 |
| 签名 / 公证 / 静默自动安装 | 不对外分发；更新只做检查 + 下载 + 用户确认安装 |
| 云同步 / 账号 / 协作 | 与纯本地定位冲突 |
| 遥测 / 崩溃上报 | 隐私承诺；崩溃日志只留本机 |
| 视频转码 / 图片编辑 | 系统工具已够用，依赖与体积不划算 |

## ADR-012 · 人像：模型不进 DMG、前后处理自实现

**决策**：人脸识别用 `onnxruntime-node` + InsightFace **buffalo_sc**（SCRFD 检测 + ArcFace 特征）。
DMG 只带原生运行时（`asarUnpack`），约 15MB 的模型在用户首次进入「人像」并确认后，由主进程下载、校验 SHA256 再解压到 `userData/models/`。
下载优先走 GitHub 加速镜像（`ghproxy.net` / `ghfast.top`），失败再回落官方 Release；镜像只是传输通道，**SHA256 是唯一信任锚**。
SCRFD 后处理、五点对齐、ArcFace 归一化与余弦聚类全部用 JS 实现，不引 Python 科学计算栈。

**理由**：
- 模型不进包，安装包保持干净，模型也能独立更新；代价只是首次多一次下载。
- InsightFace 是 Python 库，Node 不能直接 `require`；与其引入 Python 运行时或重量级移植，不如只移植确定性的前后处理（解码 / 对齐 / 归一化）。
- 相册量大时原生 onnxruntime 在 Apple Silicon 上比 JS 后端更快、更稳，内存峰值也更可控。

**后果**：
- 原生库必须解包（`onnxruntime_binding.node` 与 `.dylib` 进 `asarUnpack`），否则打包后加载失败；非 macOS 二进制与冗余 dylib 在打包时裁掉。
- 检测 / 对齐复用已按 EXIF 摆正的缩略图，不直接读原图，避免方向错误并利用缩略图缓存。
- 封面裁成 160×160 JPEG 走 `pm://local/face`，特征向量只留在主进程的 `faces.json`，渲染层只拿人物摘要与 `fileId`。
- 聚类阈值定在余弦相似度 **0.36**：测试人像上同人约 `0.35`、异人低于 `0.14`；阈值偏保守，宁可多分一组（可合并）也不把两个人并到一起。
- 失败语义：模型下载失败、路径未授权、推理失败都要在页面上可见，不静默跳过；扫描串行执行，可取消。
- 下载线路：国内网络会把 `release-assets.githubusercontent.com` 解析到不可用地址，因此镜像优先、官方回落；单条线路失败（含 SHA256 不匹配）自动换下一条，全部失败时提示「无法连接下载服务器，请检查网络后重试」。

**守卫**：`tests/main-process/face-algorithms.test.cjs`（张量、三 stride 解码、NMS、对齐、归一化、聚类、索引键）、`tests/main-process/face-model-store.test.cjs`（下载线路顺序、错误文案、目录布局）。
