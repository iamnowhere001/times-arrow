# v0.6.3 · 更新检查与应用内更新

## Context

当前版本 0.6.2 只能手动下载 DMG，用户无法在应用内知道有没有新版本。本次为 v0.6.3 增加：

1. 启动后静默检查一次 GitHub Releases，有新版本时用非阻塞提示告知；
2. 打开「检查更新」面板后可查看版本、更新说明、下载 DMG（带进度、可取消），下载完成后自动打开 DMG 引导拖入「应用程序」；
3. 更新检查可在面板中关闭（默认开启）。

已确认的关键决策：

- **不做原生自动更新**：项目 `identity: null`、无公证，macOS 上 electron-updater/Squirrel 无法安装更新。采用「检查 + 应用内下载 + 引导安装」。
- **仓库与资产约定**：`iamnowhere001/times-arrow` 的 latest Release；tag 形如 `vX.Y.Z`；资产名包含 `PhotoMinder-<version>-arm64.dmg`。该仓库当前没有任何 Release，因此「暂无发布」必须是一等状态，不能报错。
- **网络边界**：更新检查是除 AI 外唯一新增的可选联网能力，只由主进程发起，不涉及遥测；默认开启、可关闭，并在 README 隐私声明中如实写明。

## 主进程

### 新增 `electron/main/updater.cjs`

工厂函数 `createUpdater({ app, shell, logger, send })`，保持与 `ai.cjs` / `data-assets.cjs` 相同的依赖注入风格。导出：

- `registerUpdaterIpc({ handle, ok, fail })`
- `dispose()`（退出前中止下载并清理未完成的临时文件）

内部实现要点：

- `compareVersions(a, b)`：剥离 `v` 前缀，按数字段比较；非法版本返回 `null`。
- `checkForUpdates()`：
  - `GET https://api.github.com/repos/iamnowhere001/times-arrow/releases/latest`；
  - 头：`Accept: application/vnd.github+json`、`User-Agent: PhotoMinder-Updater`；
  - 15s 超时（`AbortController`，复用 `ai.cjs` 的写法）；
  - 404 → `status: 'no-release'`（仓库尚无 Release，属正常状态）；
  - 403 / 限流 / 网络错误 → 抛出可读中文错误；
  - `tag_name` 与 `app.getVersion()` 比较；`prerelease` / `draft` 不作为更新目标；
  - 从 `assets` 里选择 DMG：优先 `arm64`，优先精确名 `PhotoMinder-<version>-arm64.dmg`；
  - 资产 URL 必须是 `https:`，且 host 在 `github.com` / `objects.githubusercontent.com` / `release-assets.githubusercontent.com` 内，否则视为无可用资产；
  - release notes 截断到 4000 字符后返回。
- `downloadUpdate()`：
  - 目录 `app.getPath('downloads')`；文件名取 `path.basename(asset.name)` 并强制 `.dmg`；
  - 先写 `<name>.download` 临时文件，校验 `content-length` / `asset.size` 后 `rename` 为正式文件；失败或取消都删除临时文件；
  - 已存在同名且大小一致的 DMG 时直接复用，不重复下载；
  - `send('update-download-progress', { phase, received, total, percent, version, message? })` 推送进度；
  - 同一时间只允许一个下载任务；第二轮调用返回「正在下载」。
- `cancelDownload()`、`getDownloadState()`。
- `openDownloaded()` / `revealDownloaded()`：只使用模块内部记录的本机路径，**不接受渲染层传路径**；打开前 `stat` 确认存在。
- `openReleasePage()`：只打开本次 API 返回并校验过的 GitHub URL（allowlist）。

没有任何 IPC 接收渲染层路径，因此不需要 `isPathAuthorized()`；这一点要在注释中写明，避免后来者误加路径参数。

### 修改 `electron/main/main.js`

- `require('./main/updater.cjs')`，在 `createWindow` 之后以 `send: (channel, payload) => mainWindow?.webContents?.send(channel, payload)` 注入；
- `registerUpdaterIpc({ handle, ok, fail })`；
- `app.on('before-quit', () => updater.dispose())`；
- 菜单「设置」下新增「检查更新…」，`mainWindow?.webContents?.send('update-open-panel')`。

CSP 不需要改动：请求全部由主进程发出，渲染层 `connect-src` 仍为 `'self' pm:`。

## 渲染层

### IPC 契约（四处同步）

- `electron/preload.js` 新增：
  - `updateCheck()`、`updateStatus()`、`updateDownload()`、`updateCancelDownload()`、`updateOpenDownload()`、`updateRevealDownload()`、`updateOpenRelease()`；
  - 事件：`onOpenUpdatePanel(cb)`（菜单）、`onUpdateDownloadProgress(cb)`（进度），均返回取消订阅函数。
- `src/types/global.d.ts`：补方法签名，并在 `src/types/index.ts` 增加 `UpdateCheckResult` / `UpdateDownloadState` / `UpdateProgress` / `UpdatePreferences` 类型。
- `tests/main-process/ipc-contract.test.cjs` 的 `CHANNELS` 增加：
  `update-check`、`update-status`、`update-download`、`update-cancel-download`、`update-open-download`、`update-reveal-download`、`update-open-release`。

约定返回：

| 通道 | data |
| --- | --- |
| `update-check` | `{ status: 'available' \| 'up-to-date' \| 'no-release', currentVersion, latestVersion?, releaseName?, releaseNotes?, releaseUrl?, publishedAt?, asset? }` |
| `update-status` | `{ currentVersion, latest: 上次检查结果 \| null, download: UpdateDownloadState }` |
| `update-download` | `{ started: true }` |
| `update-cancel-download` | `{ cancelled: boolean }` |
| `update-open-download` | `{ opened: boolean }` |
| `update-reveal-download` | `boolean` |
| `update-open-release` | `boolean` |

### 新增 `src/hooks/useUpdateChecker.ts`

- 状态：`checkResult`、`isChecking`、`downloadState`、`error`、`isModalOpen`、`autoCheck`。
- 启动时读取一次 `loadPersistedConfig()`，`updatePrefs.autoCheck !== false` 时延迟 5s 静默检查：
  - 有新版本 → `showToast('发现新版本 vX.Y.Z', 'info', { label: '查看更新', onClick: openModal })`；
  - 已是最新 / 暂无发布 / 网络失败 → 不提示（只写日志）。
- `checkNow()`：手动检查，结果在面板内展示。
- `startDownload()` / `cancelDownload()` / `openDownloaded()` / `revealDownloaded()` / `openReleasePage()`。
- 订阅 `onUpdateDownloadProgress`，下载完成时 Toast 提示并提供「打开磁盘映像」。
- `setAutoCheck(enabled)` → `savePersistedConfig({ updatePrefs: { autoCheck: enabled } })`。

### 新增 `src/components/modal/UpdateModal.tsx`

复用 `ModalShell`（zIndex 80），展示：

- 当前版本（来自 IPC，不硬编码）与最新版本；
- 「启动时自动检查」开关（写入 `updatePrefs.autoCheck`）；
- 状态分支：检查中 / 已是最新 / 暂无发布 / 可更新（更新说明按纯文本渲染，绝不 `dangerouslySetInnerHTML`）/ 下载中（进度 + 取消）/ 已下载（打开 DMG + 在访达中显示 + 安装引导）/ 失败（错误文案 + 重试）；
- 无 DMG 资产时降级为「前往发布页」。

### 修改 `src/App.tsx` 与 `src/hooks/useKeyboardShortcuts.ts`

- App 中调用 `useUpdateChecker({ showToast })`，渲染 `<UpdateModal />`；
- 新增 `isUpdateModalOpen` 并传入 `useKeyboardShortcuts`，打开时禁用底层快捷键；
- 订阅菜单事件 `onOpenUpdatePanel` 打开面板。

### 配置

`src/types/index.ts` 的 `PersistedConfig` 增加可选字段 `updatePrefs?: { autoCheck?: boolean }`。读取默认值 true；字段缺失不触发迁移，`CONFIG_VERSION` 不变。

## 风险与边界

- 匿名 GitHub API 限流 60 次/小时：启动只检查一次，手动检查才会追加，足够个人使用；限流时给出可读提示。
- 未签名更新包首次启动仍受 Gatekeeper 影响，与当前手动安装体验一致；面板中明确写出「右键 → 打开」的兜底说明。
- 不实现静默覆盖安装，避免未签名应用在替换 `/Applications` 时失败并留下不可用安装。
