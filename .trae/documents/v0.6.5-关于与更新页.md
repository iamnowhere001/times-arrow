# v0.6.5 · 「关于与更新」页

## Context

应用目前没有一处集中介绍自己的地方：功能、特色、操作技巧散落在 README 与快捷键总览里，迭代计划只在 `ROADMAP.md`，更新记录只在 `CHANGELOG.md`，而这两个 md 都被 `package.json` 的 `build.files` 白名单排除（`!**/*.md`），装进 DMG 后渲染层读不到。用户要的是：左栏加一个入口，一页看完「主要功能 / 特色 / 操作技巧 / 迭代计划 / 版本更新记录 / 版本检查与更新」。

因此本次把内容以**静态 TS 数据**形式打包进 `dist`，新增一个整页视图，并把已有的更新检查能力（`useUpdateChecker` + `UpdateModal`）以只读方式接进来，不复制更新逻辑。按用户选择：左栏**新增「应用」分区**、内容用**整页视图**、本次**只开发不发版**。

## 交互与信息架构

- 左栏新增分区「应用」，一行「关于与更新」（ⓘ 图标 + 右侧箭头），`NavRow` 样式与「视图」分区一致。
- 点击后 `mainView = 'about'`，整页接管主内容区（与时光画廊 / 相似照片同构）：左栏按现有规则收起（`isLeftPaneOpen === false`），顶栏左上角返回图库。
- 页面自上而下：Hero（名称 / 副标题 / 一句话定位 / 三条承诺 + 当前版本）→ 主要功能（8 张卡）→ 特色（4 条）→ 操作技巧（6 条）→ 迭代计划（3 条，带状态标签）→ 更新记录（最近 5 个版本）→ 版本与更新（当前版本、自动检查开关、检查更新、打开发布页、未签名说明）。

## 文件改动

### 新增

1. `src/lib/about/aboutContent.ts`
   - 导出类型：`AboutEntry`（title + description）、`RoadmapItem`（version / theme / summary / status: '已完成' | '进行中' | '计划中'）、`ReleaseNote`（version / date / highlights）。

   - 版本要点取自 `CHANGELOG.md` 的人工摘要（0.6.5 / 0.6.4 / 0.6.3 / 0.6.2 / 0.6.1），迭代计划取自 `ROADMAP.md`（v0.7.0 整理版 = 进行中，v0.8.0 身份层 = 计划中，v1.0 数据健康 = 计划中）。

2. `src/components/about/AboutView.tsx`
   - Props 全部注入：`currentVersion`、`autoCheck`、`isChecking`、`onBack`、`onCheckUpdate`、`onToggleAutoCheck`、`onOpenRelease`。

   - 版本号唯一且降序；每个版本至少 1 条要点；`roadmap` 非空且 status 合法。
   - 静态断言 `AboutView.tsx` 源码不含 `window.electronAPI`、不含 `#` 开头的十六进制色值。

## 不做的事

- 不发版：不构建 DMG、不打 tag、不上传 Release（用户选择「先只开发」）。
- 不新增 Modal（`designTokens.test.ts` 固定 modal 目录 10 个 tsx）。
- 不改主进程 / IPC / 更新器：关于页只是消费 `useUpdateChecker` 已有能力。
- 不在关于页内提供跳转到其他视图的入口（侧栏此时不渲染，进去出不来）。
